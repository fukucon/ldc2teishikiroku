# 充填停止記録アプリ v2 (ldc2teishikiroku)

充填ライン (2L / 500ml) の停止記録を取るタブレット向け Google Apps Script Web App。
日報単位 (cycle) で停止ログを蓄積し、月次分析・CSV エクスポートまで一気通貫で行う。

---

## 共通リソース（他アプリとの連携のため最重要）

このアプリは **共通マスタースプレッドシート** を **他のアプリと共有** している。
スキーマや使用ルールはここを参照すること。

| リソース | ID / 場所 | 所有 | 役割 |
|---|---|---|---|
| 共通マスタースプシ | `CONFIG.MASTER_SS_ID` (`code.gs`) | 共有 | 部署/社員/商品などの参照系マスター |
| アプリDB スプシ | `CONFIG.APP_SS_ID` (`code.gs`) | このアプリ専用 | 日報ヘッダー / 停止ログ / 変更履歴 / 自由入力マスタ |

### 共通マスタースプシ 内のシート（このアプリが利用）

| シート名 | 列 (A→) | 所有者 | このアプリの用途 |
|---|---|---|---|
| `部署マスタ` | 部署コード / 部署名 / 関連ライン / 有効 | 共有 | 端末識別、日報作成時の部署選択 |
| `社員名簿` | (任意) 部署列を含む | 共有 | 部署マスタが無いときの fallback |
| `商品マスター` | 商品ID / 商品名 / 種別 (2L/500ml) / 商品通称 / バーコード / 有効 | 共有 | 日報の商品設定、品種切替（有効列が `FALSE` の行は選択肢から除外）。※列はヘッダー名で解決するため並び替え・列挿入に強い |
| `管理者名簿` | 氏名 / メール / 権限レベル(一般/リーダー/全権) | 共有 | 確定済日報の編集権限判定（リーダー以上が編集/解除可） |

**他のアプリも触る可能性があるシート。列の追加・変更は連携相手に必ず周知すること。**

### アプリ DB 内のシート（このアプリ専用）

| シート名 | 列定義 | 説明 |
|---|---|---|
| `日報ヘッダー_YYYY` | `HEADER_COLS` (24列) | 1日報=1行、年ごとにシャーディング |
| `停止ログ_YYYY` | `LOG_COLS` (21列) | 停止記録1件=1行、年ごとにシャーディング |
| `変更履歴_YYYY` | `HISTORY_COLS` (8列) | 既存値の上書き履歴、年ごとにシャーディング |
| `停止設備マスタ` | `MASTER_FREE_COLS` | 停止設備の選択肢 (select 固定、自由入力無) |
| `停止理由マスタ` | `MASTER_FREE_COLS` | 停止理由の選択肢 (オートコンプリート、自由入力可) |
| `対応内容履歴` | `MASTER_FREE_COLS` | 対応内容のオートコンプリート候補 |
| `担当マスター` | `MASTER_FREE_COLS` | 担当者名のオートコンプリート候補 |

## サイクルID 命名規則

### 新形式（現行）

```
{ライン}-{月}C{その月の連番}
```

| 例 | ライン | 月 | 連番 |
|---|---|---|---|
| `2L-5C1` | 2L | 5月 | 1本目 |
| `2L-5C2` | 2L | 5月 | 2本目 |
| `500-6C1` | 500ml | 6月 | 1本目 |

月が変わると連番は 1 にリセット。

### 旧形式（互換読み取り）

```
{ラインprefix}{YYYYMMDD}[-v{n}]
```

| 例 | ライン |
|---|---|
| `A20260522` | 2L |
| `B20260601` | 500ml |
| `A20260522-v2` | 2L (重複時の v2) |

旧形式 ID は `code.gs` の `_yearFromCycleID` / `_cycleFromLogID` / `_cycleLineMatches` が吸収し、バックエンドで透過的に処理される。

### ログID

```
{サイクルID}-{seq}
```

例: `2L-5C1-1`, `2L-5C1-2`, `A20260522-1`

## 主要機能

### 停止記録ページ (stop_record.html)

- **停止記録の追加・編集・削除**（LockService で排他制御）
- **BPM 入力**: 2L のみ、停止設備の左に表示。0/80/60/40/20 のドロップダウン（自由入力無）
- **品種切替**: 停止設備で「品種切替」を含む設備を選択すると商品選択モーダルが開き、対応内容に `旧商品名→新商品名` を自動入力
- **製造開始/終了**: 担当者・廃棄本数・日時を入力。入力中はすべての入力保護（softMerge）
- **製造終了入力時**: 未確定の場合は確定ボタンをパルスアニメーションで強調 + モーダル通知
- **日報確定 / 解除**: 確定後は一般ユーザー読み取り専用。リーダー/全権ユーザーのみ編集・解除可
- **未入力 ! マーク**: 必須フィールドが空の場合、フォーム背景ピンク + 赤い `!` バッジ
- **フッター**: 未送信件数 + 未入力（! マーク）件数を中央表示
- **一覧モーダル**: 左下の `□` ボタンで停止記録のテーブル一覧表示（BPM列は 2L のみ）
- **現時刻ボタン**: スタート時刻横の小ボタンで現在時刻を即入力
- **自動更新**: 30秒ごとに poll。タブ非表示時は完全停止、表示時に再開
- **オートコンプリート**: カスタム JS 実装（Safari の datalist 遅延問題を回避）

### インデックスページ (index.html)

- 日報一覧のページネーション（20件/ページ）
- 新規日報作成（ライン・日付・部署・商品を選択）
- 印刷ボタン: 一時スプシを作成→PDF URL 取得→表示後即削除（Drive API v3 DELETE）
- 削除ボタン: 確認モーダル付き

### 分析ページ (analysis.html)

- ライン・月・日付・設備・理由でフィルタ
- 停止記録一覧テーブル（ID / 月日 / 商品 / ストップ / スタート / 分 / MF温度 / TEA温度 / 停止設備 / 停止理由 / 対応内容）
- CSV エクスポート（ブラウザ完結、権限ダイアログなし）

## 重要な設計判断

| 項目 | 内容 |
|---|---|
| **DB アクセス** | `executeAs: USER_DEPLOYING`（開発者が実行）— 他アカウントに DB を直接触らせない |
| **キャッシュ** | ScriptCache に 6時間（最大値）+ localStorage 永続。手動更新ボタンで強制リフレッシュ |
| **排他制御** | LockService で書き込み競合を防止 |
| **商品スナップショット** | 日報・品種切替 stop には商品情報を書き込み時点でコピー保存。マスター更新の影響を受けない |
| **停止設備** | select 固定（自由入力不可）。停止理由はオートコンプリート（自由入力可） |
| **BPM** | 2L ライン専用（LOG_COLS[20], U列）。500ml には列は存在するが入力 UI 非表示 |
| **MF温度** | 旧名 UF温度。DB 列ヘッダーも手動で変更済みであること |
| **Screen Wake Lock** | タブレット画面オフ防止（1時間、UI なし） |
| **印刷一時ファイル** | 表示後に Drive API v3 DELETE で即削除。溜まった場合は `cleanupPrintTempFiles()` を手動実行 |
| **変更履歴** | 旧値が空でなく旧値≠新値のときのみ `変更履歴_YYYY` に記録 |

## デプロイ

Google Apps Script の Web App としてデプロイ:

- **実行者**: 自分 (USER_DEPLOYING) — DB は開発者のドライブにあり、他アカウントに直接触らせない
- **アクセス**: 同じドメイン全員（または ANYONE）
- `Session.getActiveUser().getEmail()` を使用するため Workspace ドメイン内アクセスが前提
- clasp 非対応環境（社内制限）のため、コードはスクリプトエディタに手動コピー

## 外部スプレッドシート同期 (`sync.gs`)

ライン横断の分析・上長共有用に、別スプシ (`EXTERNAL_SYNC_CONFIG.EXTERNAL_SS_ID`) の **`2L` / `500`** シートへ差分転送する仕組み。

- **トリガー**: 3時間ごとの時間トリガー (`syncToExternalSpreadsheet`)
- **差分キー**: `HEADER_COLS['最終更新']`（停止ログ追加・編集・確定・解除でも親側がこの値を更新するので一発で拾える）
- **書き出し単位**: 「サイクル1行 + 直下に停止ログ複数行」のブロック。同一CycleIDのブロックを丸ごと置換することで再書込時の整合性を担保
- **書き出しレイアウト**: `SYNC_COLS` (25列) — A列=種別(`日報`/`└停止`)、B列=サイクルID(置換キー)、以下日付/時刻/各種項目を共通スキーマで並べる
- **並び順**: 同期処理ごとに更新分を製造日 desc で2行目以下に挿入するため、最新の動きが常に上に積み上がる
- **状態**: `PropertiesService` の `EXTERNAL_SYNC_LAST` に最終同期時刻を保存

### セットアップ（Apps Script エディタから1回）

```
setupExternalSyncTrigger()    // 3時間トリガー作成
syncToExternalSpreadsheet()   // 動作確認: 初回は全件転送される
```

### 運用関数

| 関数 | 用途 |
|---|---|
| `syncToExternalSpreadsheet()` | 差分同期を即実行（トリガーから自動でも呼ばれる） |
| `setupExternalSyncTrigger()` | 3時間トリガーを作り直す |
| `removeExternalSyncTrigger()` | トリガー解除 |
| `resetExternalSyncCheckpoint()` | 最終同期時刻をクリア。次回sync時に全件再転送 |
| `showExternalSyncStatus()` | 最終同期時刻・トリガー数を Logger に出す |

## 開発・運用メモ (AI セッションへの注意点)

1. **共通マスタースプシのスキーマを勝手に変えない**。列追加・削除は他アプリへの影響を確認してから
2. `HEADER_COLS` / `LOG_COLS` / `HISTORY_COLS` は **末尾追加のみ** で運用。途中挿入は既存データを壊す
3. スキーマ変更後は `setup.gs → migrateSchema()` を手動実行してからコミット
4. サイクルID の旧形式 (`A20260601`) と新形式 (`2L-5C1`) を両方ハンドルすること — `_yearFromCycleID` / `_cycleFromLogID` / `_cycleLineMatches` を参照
5. BPM は 2L のみ — 500ml のコードパスに BPM UI を混入しないこと
6. `CONFIG.APP_SS_ID` は本番 DB のスプシ ID。テストは別スプシを使うこと
