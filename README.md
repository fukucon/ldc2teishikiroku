# 充填停止記録アプリ v2 (ldc2teishikiroku)

充填ライン (2L / 500ml) の停止記録を取るタブレット向け Google Apps Script Web App。
日報単位 (cycle) で停止ログを蓄積し、月次分析・CSV エクスポートまで一気通貫で行う。

---

## 🔗 共通リソース（他アプリとの連携のため最重要）

このアプリは **共通マスタースプレッドシート** を **他のアプリと共有** している。
スキーマや使用ルールはここを参照すること。

| リソース | ID / 場所 | 所有 | 役割 |
|---|---|---|---|
| 共通マスタースプシ | `CONFIG.MASTER_SS_ID` (`code.gs`) | 共有 | 部署/社員/商品/リーダー権限などの参照系マスター |
| アプリDB スプシ | `CONFIG.APP_SS_ID` (`code.gs`) | このアプリ専用 | 日報ヘッダー / 停止ログ / 自由入力マスタ |

### 共通マスタースプシ 内のシート（このアプリが利用）

| シート名 | 列 (A→) | 所有者 | このアプリの用途 |
|---|---|---|---|
| `部署マスタ` | 部署コード / 部署名 / 関連ライン / 有効 | 共有 | 端末識別、日報作成時の部署選択 |
| `社員名簿` | (任意) 部署列を含む | 共有 | 部署マスタが無い時の fallback |
| `商品マスター` | 商品ID / 商品名 / 種別 (2L/500ml) / 商品通称 | 共有 | 日報の商品設定、商品切替 |
| `リーダー権限` | 氏名 / メールアドレス | 共有 | 確定済日報の編集権限判定 |

⚠️ **他のアプリも触る可能性があるシート。列の追加・変更は連携相手に必ず周知すること。**

### アプリ DB 内のシート（このアプリ専用、年シャーディング含む）

| シート名 | 列定義場所 | 説明 |
|---|---|---|
| `日報ヘッダー_YYYY` | `code.gs` の `HEADER_COLS` | 1日報=1行、年ごとにシャーディング |
| `停止ログ_YYYY` | `code.gs` の `LOG_COLS` | 停止記録1件=1行 |
| `日次サマリ` | `code.gs` の `SUMMARY_COLS` | (現状未集計) |
| `停止設備マスタ` / `停止理由マスタ` / `対応内容履歴` | `MASTER_FREE_COLS` | 自由入力 + 使用回数 |

## 命名規則

| 規則 | 例 |
|---|---|
| サイクルID | `{ラインprefix}{YYYYMMDD}` (`A` = 2L, `B` = 500ml)<br>例: `A20260522` / 重複時: `A20260522-v2` |
| ログID | `{cycleID}-{seq}`<br>例: `A20260522-1` |
| キャッシュキー | `master_XXX_v1` (共通スプシ系は ScriptCache 6時間) |
| localStorage キー | `cached_XXX_v1` (フロント側マスタ) |

## 重要な設計判断

- **キャッシュ**: マスタ系は ScriptCache に **6時間** (最大値) + localStorage 永続。手動更新ボタンで強制リフレッシュ可
- **自動更新**: 停止記録ページは 15秒ごとに poll、入力中フィールドは保護 (`softMerge`)
- **画面オフ防止**: Screen Wake Lock API (1時間)、サイレント (UI なし)
- **オフライン**: 通信失敗時は 接続状態ピル を赤に。書き込みは未対応
- **商品スナップショット**: 日報・商品切替stop には商品ID/名/種別/通称を **書き込み時点でコピー保存**。マスター更新の影響を受けない
- **日報確定 + リーダー権限**: 全フィールド埋まり後に「確定」 → 一般ユーザーは編集不可、`リーダー権限` シートに登録されたメールのユーザーだけ編集/解除可能

## セットアップ / マイグレーション

```js
// 初回
setup.gs::setupDatabase();        // シート作成
setup.gs::_seedSampleMasters();   // 任意: サンプル停止設備/理由など投入

// 既存シートに列追加（HEADER_COLS / LOG_COLS を変更した時）
setup.gs::migrateSchema();
```

新規セットアップ時の必要シート (共通スプシ側):
- `部署マスタ` (任意、なくても 社員名簿 fallback)
- `商品マスター` (必須、種別フィルタに利用)
- `リーダー権限` (任意、未設定時は全員「一般」扱い)

## デプロイ

Google Apps Script の Web App としてデプロイ:
- 実行者: **自分 (developer)**（DB は自分のドライブにあり、他アカウントに直接触らせない）
- アクセス: 必要に応じて「同じドメイン全員」など
- `Session.getActiveUser().getEmail()` を利用するため、Workspace ドメイン内アクセスが前提

CSV出力はブラウザ完結のためデプロイ設定の影響を受けない（権限ダイアログも出ない）。

## 開発・運用メモ (AI セッションへの注意点)

このリポジトリで Claude などの AI コーディングセッションを開く場合:

1. **共通マスタースプシのスキーマを勝手に変えない**。列追加・削除は他アプリへの影響を確認してから
2. `HEADER_COLS` / `LOG_COLS` の **末尾追加のみ** で運用。途中挿入は既存データを壊す
3. スキーマ変更後は `setup.gs::migrateSchema()` の動作確認をしてから commit
4. 共通スプシ系の列を読む箇所はだいたい `_getProducts` / `_getDepartments` / `_getLeaders` に集約してある
